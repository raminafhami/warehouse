# پیش‌نویس تصمیم معماری P01

وضعیت: استک انتخاب‌شده برای طراحی P01. تأیید G1 پس از تکمیل بستهٔ معماری ثبت می‌شود.

## استک

- رابط کاربری: React، React Router و Vite با JavaScript. صفحات فارسی و راست‌به‌چپ با CSS Modules و استایل چاپ، طبق مرجع تأییدشده.
- سرور: Express روی Node.js LTS با JavaScript و معماری یکپارچهٔ ماژولار. API نسخه‌دار زیر `/api/v1` و قرارداد OpenAPI. اعتبارسنجی ورودی، احراز هویت و بررسی مجوز در سرور انجام می‌شوند.
- داده: MongoDB مستقل در حالت replica set و Mongoose. تغییر مانده، ثبت دفتر گردش و تغییر وضعیت سند در یک تراکنش انجام می‌شوند. شاخص یکتا، کنترل نسخه و کلید تکرارناپذیری فرمان جلوی اثر دوباره و رقابت بر سر آخرین موجودی را می‌گیرند.
- اجرا و تست: Docker Compose برای توسعه و محیط آزمایشی، Jest برای واحد و یکپارچه‌سازی API و Playwright برای مسیرهای مرورگر. تست تراکنش با replica set واقعی انجام می‌شود.

## مرزهای سیستم

رابط کاربری از API REVAL استفاده می‌کند. REVAL کاربران، نشست‌ها، دیتابیس و فضای ذخیرهٔ فایل مستقل دارد. سازگاری با روال در سطح قرارداد پاسخ و صفحه‌بندی، نگاشت شناسه و نقش، و مراجع خارجی طراحی می‌شود. بررسی نسخهٔ مرجع روال و آزمون قرارداد در ادامهٔ P01 انجام می‌شود.

الگوی ساختار از support-platform می‌آید. فرانت‌اند صفحات، اجزای مشترک و کلاینت API جدا دارد. بک‌اند از routes، controllers، middleware و مدل‌های Mongoose تشکیل می‌شود. سرویس‌های دامنه قواعد موجودی، حواله و تولید را مستقل از HTTP اجرا می‌کنند. Redis و سرویس‌های جدا در صورت نیاز اندازه‌گیری‌شده به G1 یا تصمیم بعدی ارجاع داده می‌شوند. نسخه‌های دقیق ابزارها هنگام آماده‌سازی محیط P02 تثبیت می‌شوند.

## ادامهٔ طراحی

مدل داده و شاخص‌ها، ماشین‌های وضعیت، قواعد دفتر گردش، ERD و نمونهٔ OpenAPI باید تکمیل شوند. سه سناریوی طراحی شامل دریافت کسری، درخواست هم‌زمان آخرین واحد و تکرار فرمان صدور حواله بررسی خواهند شد. محل استقرار و هدف ظرفیت در G1 بررسی می‌شوند.
