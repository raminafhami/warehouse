# بستهٔ بررسی G1

نسخهٔ ۲، 2026-11-19. وضعیت: تأییدشده. متن تأیید مالک: «مود تاییده / شروع کن».

P01 مدل داده و رفتارهای اصلی را برای استک مصوب JavaScript طراحی کرده است. [استک](P01/ADR-001-STACK.md)، [مدل داده و ERD](P01/DATA-MODEL.md)، [گردش وضعیت](P01/STATE-MACHINES.md)، [طراحی موجودی](P01/INVENTORY-DESIGN.md) و [OpenAPI اولیه](P01/openapi.json) مبنای بررسی‌اند.

## رفتارهای قابل بررسی

1. محمولهٔ ۱۰‌تایی را با ۸ قطعه سالم دریافت کنید. موجودی ۸ و کسری باز ۲ است.
2. دو اپراتور هم‌زمان آخرین قطعهٔ آزاد را بخواهند. یکی رزرو می‌کند و درخواست دیگر کمبود می‌گیرد.
3. پاسخ صدور حواله در شبکه گم شود. تکرار فرمان با همان شناسه همان حواله را برمی‌گرداند و اثر موجودی یک بار ثبت می‌شود.
4. صادرکننده بخواهد همان حواله را دریافت کند. رد می‌شود. گیرندهٔ مجاز، مقدار پذیرفته‌شده را وارد خط می‌کند و کسری برای رسیدگی باز می‌ماند.
5. قطعه به سبد تخصیص پیدا کند و بعد نصب شود. تخصیص از خط به سبد و نصب از سبد به مصرف همان گوشی ثبت می‌شود.

این بررسی طراحی است. بررسی رفتار واقعی در بک‌اند و رابط کاربری از مرحلهٔ مربوط اجرا می‌شود.

## قراردادهای فایل، چاپ و گزارش

- بارنامه و شاهد همتا در فضای فایل پایدار REVAL ذخیره می‌شوند. متادیتا شامل اندازه، نوع تأییدشده، checksum، شناسهٔ عامل و کلید فایل است. بارگیری از API و پس از بررسی مجوز سند انجام می‌شود. فایل ابتدا در فضای موقت وارد می‌شود و پس از ثبت رابطه در دیتابیس برای بازیابی در دسترس است. پاک‌سازی فایل‌های موقت با مهلت مشخص انجام می‌شود.
- قالب چاپ برای هر نوع برچسب و سند نسخه دارد. چاپ مجدد با همان شناسه ثبت می‌شود. اسکن برچسب کالا یا بسته فرمان جداگانه است. اندازهٔ دقیق لیبل و مدل چاپگر پس از دریافت مشخصات D06 تثبیت می‌شوند.
- گزارش و خروجی از همان فیلتر، منطقهٔ زمانی و کنترل دسترسی فهرست استفاده می‌کنند. موجودی گزارش از ماندهٔ سازگار با دفتر گردش خوانده می‌شود. خروجی گزارش از طریق API مجوزدار تولید می‌شود.
- نشست سمت سرور و کوکی HttpOnly استفاده می‌شود. درخواست‌های تغییردهنده نیازمند بررسی Origin و مجوز محدوده‌اند. ابطال نشست در خروج، تغییر رمز و غیرفعال‌سازی حساب اعمال می‌شود. ثبت دستی نتیجهٔ همتا مطابق D02 به کد رهگیری واقعی نیاز دارد.

## تصمیم‌های پیش روی G1

1. **موجودی و مصرف.** آیا کسری دریافت/تحویل به‌صورت مغایرت باز بماند و قطعه پس از نصب موفق مصرف‌شده ثبت شود؟ مبنا رفتارهای بالا و [سند موجودی](P01/INVENTORY-DESIGN.md) است.
2. **محیط.** برای ساخت و تست اولیه، Docker Compose و MongoDB replica set محلی با یک سازمان پیشنهاد می‌شود. Node.js و npm در محیط فعلی در دسترس‌اند. Docker CLI و اجرای Compose روی این سیستم هنوز تأیید نشده‌اند. ظرفیت ۳ خط و ۵۰ کاربر هم‌زمان فرض اولیهٔ طراحی است. ظرفیت نهایی بعد از اندازه‌گیری و سرور عملیاتی، نگهداری فایل‌ها و RPO/RTO قبل از پایلوت مشخص می‌شوند.
3. **سازگاری با روال.** پیشنهاد این است REVAL مستقل ساخته شود و کامیت `dd8198e` از سورس محلی `nooraback` مبنای نگاشت کاربران، گروه‌ها، شعبه‌ها و مجوزها باشد. نگاشت با نسخهٔ عملیاتی روال پیش از اتصال بازبینی می‌شود. [قرارداد سازگاری](../ROVAL-COMPATIBILITY.md)

ساختار OpenAPI با Swagger CLI اعتبارسنجی شد. سناریوهای موجودی در سطح طراحی مرور شدند. نسخهٔ ۲ این بسته مبنای ساخت P02 در مخزن مستقل `../reval-app` است.
