# قواعد عملیات (command) استخراج‌شده از پروتوتایپ

منبع: `evidence/P00/command-rules.json` — اسکن ایستای bundle؛ `…` جای مقدار متغیر در پیام است. 73 عملیات، 214 پیام رد/شکست.

هر سطر «شکست» یعنی پروتوتایپ در آن شرایط عملیات را رد می‌کند. بازپیاده‌سازی باید همین قاعده را **در Backend** اعمال کند، مگر در DEVIATIONS خلاف آن تصمیم شده باشد. شناسه CMD با ستون api/notes در TRACEABILITY مرتبط است.

## اطلاعات پایه (`master`)

### CMD-001 — تعریف نوع قطعه  
مجوز: `master:create`

- رد: کد اختصاری باید ۲ تا ۴ حرف لاتین بزرگ باشد (مثلاً BAT).
- رد: کد … قبلاً تعریف شده است.
- رد: نام قطعه الزامی است.

### CMD-002 — تغییر وضعیت نوع قطعه

- رد: نوع قطعه یافت نشد.

### CMD-004 — تعریف قطعه (کد کالا)

- رد: تأمین‌کننده را انتخاب کنید.

- رد: مشخصه فنی قطعه را وارد کنید (مثلاً 1020mAh · 3.7V).
- رد: کد کالا فقط حروف لاتین، عدد و خط تیره (حداکثر ۲۴ نویسه).
- رد: کد کالای … قبلاً تعریف شده است.

- رد: قطعه … غیرفعال است.
- رد: برای «…» ایستگاهی در خط تعریف نشده است.
- رد: BOM بدون «…» قابل ثبت نیست.
