## خط پایهٔ محلی

ویندوز ۱۰ Enterprise LTSC، Intel i5-9500 با ۶ پردازندهٔ منطقی، حدود ۲۴ گیبی‌بایت RAM، Node 22.19 و MongoDB 8 replica set تک‌گره روی همان دستگاه. API در فرایند جدا از مولد بار اجرا شد. دادهٔ آزمایشی شامل زنجیرهٔ کوچک مرحله‌های قبلی و ۱۶ کارتن برای ثبت اسکن موفق بود. ۱۶ کاربر هم‌زمان هرکدام ۱۲ درخواست، مجموعاً ۱۹۲ درخواست در ۱٫۱۳۱ ثانیه فرستادند. درخواست‌های مختلط بدون مکث اجرا شدند.

| جریان | نمونه | p95 میلی‌ثانیه | خطای غیرمنتظره |
|---|---:|---:|---:|
| داشبورد | ۳۵ | ۸۹ | ۰ |
| گزارش و تطبیق | ۳۶ | ۱۴۱ | ۰ |
| رهگیری | ۳۵ | ۷۵ | ۰ |
| رد اسکن تکراری | ۳۵ | ۳۹۷ | ۰ |
| تکرار فرمان ثبت‌شده | ۳۵ | ۱۱۶ | ۰ |
| اسکن موفق | ۱۶ | ۱۵۶ | ۰ |

مصرف زمان پردازندهٔ API در پنجرهٔ بار ۱۴۸۴ میلی‌ثانیه بود. RSS در نمونهٔ پایانی API حدود ۱۰۵ و MongoDB حدود ۱۹۹ MiB بود. ۱۶ عضویت یکتا، یک سند از فرمان تکراری و تطبیق همهٔ سطرهای مانده با دفتر بررسی شدند. این اندازه‌گیری پیوسته یا روی دادهٔ هم‌اندازهٔ پایلوت اجرا نشده است.

برای تکرار، روی replica set مجزای آزمایشی با TEST_MONGODB_URI معتبر، REVAL_P14_BASELINE=true را برای npm run test:integration تنظیم کنید. آزمون‌ها پایگاه تصادفی آزمایشی می‌سازند. اجرای Docker، ردیف‌های باقی‌ماندهٔ TRACEABILITY، تجهیزات D06 و آزمون ظرفیت D07 باز هستند. خروج به فروشنده مطابق D01 خارج از دامنه است.
